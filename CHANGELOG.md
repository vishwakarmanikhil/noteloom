# Changelog

All notable changes to this project are documented here. Format loosely follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/); this project follows [Semantic Versioning](https://semver.org/).

## [Unreleased]

### Added

- Pasting a raw image/media file straight from the OS clipboard (a screenshot, an OS-level "Copy Image") now inserts an `embed` block, instead of being silently dropped — previously only copying an already-rendered `<img>`/`<video>`/`<audio>` FROM A WEBPAGE (real HTML on the clipboard) worked, since `deserializeClipboard` never looked at `clipboardData.files` at all. Goes through the exact same `uploadFile`/`maxFileSize` resolution `EmbedBlock`'s own dropzone/file-input/drag-drop already uses (new shared `src/blocks/embed/resolveFileEmbed.js`), so a host's upload configuration behaves identically no matter which of the three triggered it. A real file on the clipboard takes priority over `text/html`/`text/plain` on the same paste event, since it's an unambiguous signal of direct paste intent; pasting several files at once inserts one embed block per file, and one that fails to resolve (oversized, or a rejected `uploadFile` call) is skipped rather than aborting the rest.
- Embed blocks now recognize links from a handful of common providers — YouTube, Vimeo, Loom, Figma, CodePen, and Spotify — and render a real interactive embed (iframe) instead of a broken `<img>`/`<video>` tag pointed at a page URL. Pasting one of these links into ANY embed block's URL field (image/video/audio/file, via drag/drop or the existing URL input) auto-detects it and switches the block over; a new **"Embed link"** slash command starts a block scoped to just this (no file upload, a link-only dropzone with its own hint text). Pure pattern-based URL transforms (new `src/blocks/embed/oembedProviders.js`) — no network fetch, no real oEmbed discovery/metadata, staying true to the package's zero-runtime-dependency, no-backend design. The block's toolbar gains an "Open original" link back to the pasted URL; copy/paste and HTML export represent it as a marked `<a>` (an iframe doesn't round-trip meaningfully through plain HTML), reconstructed back into a real embed block on paste into this editor.
- New **Markdown export** — `exportDocumentMarkdown(store, registry, inlineRegistry)`, plus a "Markdown" tab on `DocumentExportButton`. Headings, bold/italic/strikethrough/code/links, bulleted/numbered/to-do lists (with real nesting and GFM task-list syntax), blockquotes, fenced code blocks with their language, dividers, and GFM tables all get real Markdown syntax; block types with no natural Markdown form (canvas drawings, in particular) fall back to plain text rather than being dropped. Every built-in block type gained an optional `toMarkdown(block, ctx)` alongside its existing `toHTML`/`toPlainText` (a custom host-registered block type can add its own the same way; one that doesn't falls back to `toPlainText` automatically).
- `DocumentExportButton` gains **"Print / Save as PDF"** and **"Download Word (.doc)"** buttons — no PDF-writing or `.docx`(OOXML zip) code of its own (would mean either a runtime dependency or a large hand-rolled binary-format writer, neither fitting this package's zero-dependency design): PDF goes through the browser's own native "Save as PDF" print destination (the existing `@media print` stylesheet already hides all editor-only chrome, so what prints is just the document), and Word download uses the well-known trick of Word-flavored HTML (new `exportDocumentWordHTML`) saved with a `.doc` extension, which Word opens directly via MIME sniffing.

### Accessibility

- The embed block's media resize handle, a table column's resize handle, and the canvas block's resize handle all carried `role="slider"` with correct `aria-valuemin/max/now` — but were mouse-drag-only, with no `tabIndex` and no keyboard handler at all, so a keyboard-only user could Tab right past them and the ARIA role was actively misleading (announcing an operable slider that arrow keys did nothing to). All three are now real keyboard sliders: Left/Right (embed/table) or Left/Right/Up/Down (canvas, which resizes width and height independently) adjust by a step, Shift for a finer step, Home/End (or Home alone, for canvas) jump to the min/max.
- `CommentPopover` (the click-or-hover panel for viewing/replying to an existing comment thread) had no `role`, no `aria-modal`, and never moved focus in on open or restored it on close — a real gap for a panel that can be "pinned" open via click, not just glanced at on hover. A pinned (click-)opened popover now gets `role="dialog"`/`aria-modal="true"` and the same one-time focus-in/focus-out-on-close `Modal.jsx` already does; a hover-only preview deliberately does NOT take focus (or claim `aria-modal`) — a passing mouse-over must never steal focus from wherever the user is actually typing.
- `VersionHistory`'s drawer is a hand-rolled `role="dialog"` (not built on `Modal.jsx`, since it's a side-drawer not a centered dialog) that already had Escape-to-close but no `aria-modal`, no focus-in on open, and no focus-restoration on close — a keyboard/screen-reader user lost their place after closing it. Now matches `Modal.jsx`'s own focus handling.

## [0.3.3] - 2026-08-16

### Added

- `EditorProvider`/`NoteloomEditor` gain an `uploadFile(file, { kind }) -> Promise<{ src, name?, mimeType? }>` option — lets a host send a picked/dropped `embed` block file (image/video/audio/file) somewhere real (local disk via your own server, AWS S3, or any other cloud storage) instead of the package's zero-config default of reading it straight into a `data:` URL. Without it, behavior is completely unchanged (backward compatible). The block shows an "Uploading…" state while the returned Promise is pending, and a dismissible error (nothing written to the document) if it rejects. New `maxFileSize` option (bytes) caps the `data:` URL fallback ONLY — rejects an oversized file with a clear error instead of silently bloating the document; has no effect once `uploadFile` is configured, since the host's own function/backend owns that decision. Small/medium/large file handling is entirely `uploadFile`'s own business off `file.size` — no byte thresholds are hardcoded in the package itself, since what counts as "large" varies by app. New `useFileUpload()` hook exposes the same `{ uploadFile, maxFileSize }` for a host building its own upload UI outside `EmbedBlock`.
- `usePersistedDocument` now wires up **Ctrl+S (Windows/Linux) / Cmd+S (Mac)** to save immediately and block the browser's own "Save Page" dialog — everything already auto-saves (debounced), but the shortcut is the reflex every user reaches for regardless, and without intercepting it the native dialog popping up reads as "did that not just save?" even though it did. New `saveShortcut` option (default `true`, opt out with `false`) and `onSave` callback (fires after every save, shortcut-triggered or manual — e.g. to flash a "Saved" toast). The hook now also returns `save()` directly for a manual Save button. `createAutoPersistence`'s `flush()` now returns a Promise that resolves once the write actually lands (previously fire-and-forget), which is what makes `onSave` reliable.
- `useVoiceTyping` now accepts an `engine` option — a factory returning a `SpeechRecognition`-shaped object — for host apps whose runtime doesn't implement `window.SpeechRecognition` (or implements it non-functionally), most notably embedded webviews like Tauri's WebView2/WKWebView. Previously `isSupported` (and therefore the whole dictation UI) was hard-locked to the browser constructor's presence, with no way for a host to plug in a native/cloud recognition backend behind the same hook. Omitting `engine` keeps the existing browser-detection behavior unchanged — fully backward compatible. See the hook's doc comment for the exact interface an `engine` instance must implement.
- Two new opt-in typing-behavior hooks, same "mount once alongside your container ref" shape as the slash/emoji/@ menu triggers: `useSmartQuotes(containerRef, { enabled })` substitutes a typed straight `"`/`'` for the contextually correct curly quote (one character in, one out — except when wrapping a selection, where it inserts an open+close pair around it), and `useAutoPairBrackets(containerRef, { enabled })` auto-closes `( [ {`, skips over an already-present closer, and wraps a same-run selection. Both no-op inside `code` blocks. Off by default (`enabled` defaults to `true` when the hook is mounted at all — a host controls whether it's mounted, same pattern as every other opt-in trigger hook here).
- `EditorProvider` gains a `showLineNumbers` prop (default `false`); when on, `CodeBlock` renders a non-editable line-number gutter derived from the block's own text (display-only — the stored document shape is unchanged).
- `Select`'s option list (every dropdown/combobox in the editor — custom field types, table select columns, the built-in `select` inline type) is now windowed/virtualized: only the rows actually scrolled into view (plus a small overscan buffer) are ever mounted, regardless of how many options there are. A static list of thousands of options, or a dynamic `options` resolver's returned page, now scrolls just as smoothly as one of ten — the DOM node count no longer grows with the option count. Row height is measured once from the first real rendered row (`useLayoutEffect`, before paint) rather than hardcoded, so it stays correct for both the plain-text and `variant="tag"` pill layouts. Keyboard navigation (Arrow Up/Down keeping the active option in view) now computes the target scroll position directly instead of calling `scrollIntoView()` on the active row's own DOM node, since a virtualized item outside the current window may not be mounted at all.
- Inserting a select/custom-select/mention chip from the "/" or "@" menu now opens its picker immediately, focused and ready to search, instead of leaving the caret in the empty text past the chip (requiring a second click to actually use what you just inserted). New `Select`'s `autoOpen` prop (used internally, not something most callers need to pass themselves) and `insertInlineRunAtCursor`'s `autoOpen` option; a small new `pendingAutoOpen.js` carries the one-shot "this chip was just inserted" signal from the command's `run()` to the chip's own first mount without persisting it as document state. Checkbox/date insertion is unaffected — they keep landing the caret in the trailing text, same as before.
  - Along the way, found and fixed a real (if easy to miss) pre-existing bug this surfaced: `Select`'s "focus the search input on open" effect depended on `isOpen` alone, but the popover's `<input>` only actually mounts a render pass *later*, once its horizontal position resolves from `null` (`useHorizontalAutoAdjustedLeft`'s own measure-then-clamp). A plain click happened to dodge this by reusing an already-resolved position left over from a previous open, but a genuinely cold first open — exactly what `autoOpen` always is — hit the gap and silently focused nothing. The effect now also depends on that resolved position, so it correctly re-fires once the input actually exists.
- Picking an option on a select/custom-select/mention chip that was just inserted (auto-opened, per the above) now lands the caret right after the chip, in the trailing text of the SAME paragraph — completing the "insert a field, fill it in, keep typing" flow instead of leaving focus sitting on the chip itself. This is the same trailing-run focus a normal (non-auto-opening) insertion already does immediately; auto-opening just defers it until the picker interaction finishes. New `focusAfterChip` (`inlineTypes/shared/advanceAfterPick.js`), scoped to only the fresh-insertion case (tracked via the same one-shot signal `autoOpen` already uses) — reopening an existing chip elsewhere in the document to change its value later does not also move focus. If the chip somehow has no trailing run at all (not how a normal insertion ever leaves things), a fresh empty paragraph is inserted and focused instead, so there's always somewhere typeable rather than the caret being stranded on the chip's own non-text trigger button.
  - This replaces an earlier, wrong first attempt at this feature that jumped to a different *sibling block* instead of staying in the same paragraph — including, in the worst case, inserting a whole new paragraph when none followed. Caught from a real DOM dump showing the caret landing in an unrelated new block instead of the empty run already sitting right after the chip.
  - Follow-up fix: worked in paragraphs/headings/table cells but not list items or toggle headings, since `focusAfterChip` only looked in `block.contentIds` — a listItem/toggleHeading's own runs live in `block.props.titleRunIds` instead (`contentIds` there holds nested child list items), so the chip's run id was never found and every list-item pick fell through to the "no trailing run" fallback, creating a stray new paragraph. Now checks `titleRunIds` first, the same dual-path convention `REPLACE_RUN_SPAN`/`SET_BLOCK_RUNS` already use internally. Verified end-to-end in a real browser across paragraph, list item, and table cell.
- `FieldTypeEditorModal` (the in-editor "+ New field type" UI) gains an "Also show in @ mentions" checkbox, and the field type record it saves gains a `mentionable` boolean alongside `label`/`options` — previously there was no way to make a user-created custom select type reachable via "@" at all, even though the underlying `createSelectFieldType({ triggers })` has always supported it for host-code-registered types. `registerStoredFieldTypes` now reads `mentionable` back off each persisted field type and passes `triggers: ['slash', 'at']` accordingly when re-registering it after a reload, instead of always defaulting to slash-only.
- A "select" table column's own menu can now start from an already-created custom field type's option list instead of typing options out by hand every time: a new **"Copy options from…"** dropdown (only shown once at least one field type has been created via the in-editor "+ New field type" flow, i.e. `FieldTypeEditorModal`) copies that type's `options` into the column — a one-time copy, not a live link, so the column's own list can then be freely renamed/added-to/removed-from via the existing manager below it without touching the source field type. A **"+ New field type"** button is always shown alongside it, opening the same create dialog a chip's own "Manage options…" popover already reaches.
- A document now has its own collaboration-aware **people list** (`addPerson`/`updatePerson`/`removePerson` from `src/people/people.js`, `usePeople()` React hook) — real document data, not device-local storage: every collaborator on the same document sees and can manage the same list, the same way everyone already sees the same comment threads. Uses the exact same sync tier as comment threads (a dedicated `peopleWrite` wire envelope with existence-check-only merge in `EditorStore`, no per-field HLC needed) rather than the local-only treatment `addFieldType`/`updateFieldType`/`removeFieldType` still get. Intended as the options source for an "Assignee"-style `createSelectFieldType` usage — see that function's own doc comment for the worked example — so assignable people are consistent across everyone editing a note together instead of each person seeing their own local list.
  - Fixed a real, pre-existing bug this surfaced: any `Select` nested inside another popover (like this new dropdown, or the pre-existing "Column type" selector right above it) closed the OUTER popover the instant you picked an option — `useOutsideClickAndEscape`'s "is this click outside?" check is DOM-`.contains()`-based, and `Select`'s own popover is portaled to `document.body`, so it's never a DOM descendant of the outer popover no matter how it's nested in the React tree. The hook now also treats a click landing inside any currently-open `.be-select-popover` as "inside," fixing this for every such nesting, not just the new one.
  - Also fixed a second, unrelated pre-existing bug caught while chasing the first one down: `examples/basic`'s own hand-authored table block had no `columns` metadata in its `props` at all (unlike a table inserted via "/table", whose factory always sets it up front) — every render silently regenerated brand-new column ids, remounting each column header's menu and resetting whatever was open in it. Not something this table's own users would ever have consciously debugged, since nothing else about the table looked wrong.

## [0.3.2] - 2026-08-05

### Fixed

- Canvas block: once zoomed out past 100% (the whole 1000x1000 sheet already fits inside the view — most noticeably at MIN_ZOOM, the "Zoom out" button's own limit), dragging/wheel-panning could still scroll the view away from the sheet, leaving blank space on screen instead of the complete drawing. Panning now locks and centers on the sheet for any zoom level where it already fits entirely (`clampViewOffset` in `canvasGeometry.js`); panning at 100% zoom or while zoomed in is unaffected.
- Canvas block: pen strokes and shapes previously rendered as two hard-coded layers — every shape always painted above every stroke, regardless of which was actually drawn more recently, so there was no way to draw new ink on top of an already-placed shape (it always ended up hidden behind it). Strokes and shapes now share one interleaved stacking order (new `zOrder.js`, `nextZIndex`/`minZIndex`/`orderedDrawables`): whichever you draw more recently — pen or shape — renders on top, matching how layer-based drawing tools generally behave. Bring to front/Send to back now operate on this same shared order instead of each array's own front/back independently. Existing documents are unaffected (no `z` on their strokes/shapes yet, so they keep exactly their old "all strokes under all shapes" layout until something new is drawn into them). PNG/HTML export (`buildCanvasSVGMarkup`) uses the same order, so it always matches what's on screen.
- Also fixed a real `minZIndex` off-by-one bug caught while adding tests for the above — it could return the same value as the lowest existing item's z instead of one strictly below it.
- Voice typing (`useVoiceTyping`): manually clicking (or arrow-keying/Tab-ing) into a different block while dictation was still listening had no effect — the next dictated word kept landing at the old caret position, and the visible caret kept snapping back there. Caused by `sessionAnchorRef` (where the next dictated word goes) only ever being resolved from the live caret at `start()` or after a spoken command, never in response to the user's own manual navigation. Now a `selectionchange` listener detects a caret move this hook didn't itself just make (tracked via a new `expectedCaretRef`) and redirects the next phrase there instead.
  - Follow-up fix to the above: moving the caret away mid-utterance (before the live interim transcript had finalized) could duplicate text across both blocks — the not-yet-final guess was left sitting in the old block, and the very next interim update (always the WHOLE phrase-so-far, not just the new part) wrote the same growing transcript into the new block too. The abandoned interim guess is now silently discarded (`removeEntryTextSilently`, a caret-preserving variant of the existing revert-on-command path) instead of left behind.

## [0.3.1] - 2026-07-30

### Changed

- **Version history redesigned to be Google Docs-style — BREAKING.** Snapshots are now captured automatically after each burst of edits settles (no "type a label and save" step), each one attributed to whoever made the changes, and browsed/restored through a built-in "Version history" button + drawer instead of hand-rolled UI.
  - `createPeriodicVersionSnapshotter` (dumb fixed-interval snapshots, regardless of whether anything actually changed) is removed. Replaced by `createAutoVersionHistory({ store, docId, idleMs?, maxVersions? })` — `store` must now be a `History` instance (it reads `getHistoryLog()`/`subscribeToHistory()`), and it saves one snapshot per burst of edits once `idleMs` (default 5 minutes) of inactivity passes, not on a fixed timer.
  - New `<VersionHistory docId />` component — self-contained (mount it once anywhere under `<EditorProvider>`/`<NoteloomEditor>` and it both renders the button/drawer UI *and* owns the automatic capture for as long as it's mounted). The drawer groups versions by day, shows an avatar/author/relative-time/summary per entry, and previews a version (read-only, via a static HTML render) before restoring — restore still just calls the existing `applyDocumentTemplate`.
  - `DocumentVersion` gains `authorId`/`authorIds` (who made the changes in that version's window) and `summary` (a lightweight auto-generated "N blocks changed", not a full diff); `label` is now optional and unused by the automatic flow (kept only for anyone who wants to rename a version themselves).
  - New `History` option `defaultActorId` (+ `setDefaultActorId()`) and `useEditor`'s new `currentUserId` option: every `perform`/`performBatch` call already accepted a per-call `actorId` in its `meta`, but *no internal call site in the whole package ever actually passed one* — every edit's author was silently `null` in practice. Setting `currentUserId` once now stamps every edit for free, which is what the automatic version capture (and `useComments`-style attribution generally) relies on.

### Added

- `<VersionHistory>`'s preview now defaults to a **Changes** tab — a word-level diff against the version right before it, insertions highlighted green and deletions struck through in red (Google Docs "show changes"-style), with a **Preview** tab alongside for the previous plain read-only render. New `diffDocumentsHTML(prevDoc, nextDoc)` export is the diffing function behind it, for building a custom diff view.

## [0.3.0] - 2026-07-28

### Added

- **Templates** — document templates (starter documents for `useEditor({ doc })`/`applyDocumentTemplate`) and block templates (reusable snippets insertable via "/", `captureBlockTemplate`/`insertBlockTemplate`/`registerBlockTemplates`), both developer-definable in code and end-user-creatable/persisted. `saveTemplate`/`loadTemplate`/`deleteTemplate`/`listTemplates` add a second IndexedDB object store (`templates`, alongside the existing `documents` one — `DB_VERSION` bumped 1 → 2, additive, doesn't disturb existing persisted documents), plus `useTemplates` and a generic `TemplatePicker` list component. `registerBlockTemplates` needed zero changes to `SlashMenu`/`useSlashMenuTrigger`/`BlockRegistry` — templates register as ordinary (never-rendered) slash-command-only registry entries. New `examples/05-templates/` demonstrates the full loop (register snippets, save-as-template, pick-from-gallery, import from a JSON file).
- **Character-level text merging** — concurrent edits to the *same run* now merge via a real per-character CRDT instead of whole-value last-write-wins: two peers editing different parts of the same run, or even inserting at the exact same position, both survive and interleave identically on every peer, instead of one silently overwriting the other. Reuses `ListCrdtState` (already used to order blocks) one level down, ordering each run's own characters — one instance per run, lazily seeded from its existing plain-string value (deterministic seed ids, so independently-seeding peers always agree without coordination). `run.value` stays a plain string everywhere it's read (marks, clipboard, exports, rendering); the CRDT is purely an internal merge mechanism, not a document-format change, so persistence/templates/import-export are all unaffected. Undo/redo of a text edit now tombstones/restores the exact character ids the acting peer touched (`operations.editRunChars`) instead of replaying a stale whole-string snapshot — the fix for undo being able to clobber a peer's concurrent edit to the same run. Tombstone GC (`pruneTombstones`/`getTombstoneCount`) now covers run-level character tombstones too.
- **Comments** — `addComment`/`replyToComment`/`resolveComment`/`deleteComment` and the `useComments` hook. Highlighting a range appends the comment's id to the covered runs' `marks.commentIds` (a new, isolated `src/comments/commentMarks.js` module — marks stay a flat, non-array value everywhere else) and renders with a `.be-comment-highlight` class; a thread's own metadata (text/author/replies/resolved) is fully collaboration-aware (a new `commentWrite` envelope kind + `applyRemoteOperation` case), broadcasting live and undoing/redoing like any other edit. The highlighted *range* itself is local-only in collaboration for v1, same as every other `replaceRunSpan`-based formatting operation (bold, italic, ...) already is — not a new limitation, just an honestly-documented inherited one. `anchorRunIds` on a thread is a creation-time hint only, not re-validated after later formatting edits reshape that range.
  - A full built-in UI, opt-in via `<NoteloomEditor commentAuthorId={...} showCommentsPanel>`: the floating format toolbar's Notion-style Comment button REPLACES the whole button row with a small inline composer (`CommentComposer`), centered under the selection the exact same way the toolbar itself is (rather than trailing off wherever the button sat in a wide row); the selected text is highlighted immediately when it opens (not just after submit), and Cancel/Escape/clicking away strips that highlight back off if no thread was actually created. Clicking or hovering existing highlighted text opens a popover (`CommentPopover`, mounted automatically inside every block, mirroring the existing link hover card) with Reply/Resolve/Delete; `showCommentsPanel` adds an opt-in right-side thread list (`CommentsPanel`, `position: fixed` by default). `CommentThreadCard`/`CommentComposer`/`CommentsPanel`/`CommentAvatar` are all exported for reuse in a custom layout. `onComment` (unchanged, still available on both `NoteloomEditor` and `FloatingToolbar`) takes priority when given, for full host control instead of the built-in composer. `useCommentAuthorId()`/`EditorProvider`'s new `commentAuthorId` prop carry the configured author id down to the automatically-mounted popover, since it lives deep inside every block's own render tree.
  - Deterministically-colored initials avatars (`CommentAvatar`, `getAvatarColor`/`getInitials` — no profile-picture concept exists, so every avatar is generated from the author id string), relative-time timestamps ("2 days ago", `formatRelativeTime`), and a chat-style indented/connector-line reply layout, all built from the existing `--noteloom-*` design tokens (radius/shadow/border/accent) rather than a new visual language of their own.
  - Both `CommentPopover` and the floating toolbar's standalone composer now open with a "Comments (N)"/"Add comment" header (`CommentPopoverHeader`, shared) with an explicit close button, instead of relying only on Escape/outside-click. `CommentComposer` itself now lays out as a proper comment box — an auto-growing textarea (2 rows to start, up to 5, then scrolls) with Send/Cancel on their own row below, not a single-line chat pill — and submitting or canceling now also clears the native text selection (blurring first, since `useFloatingToolbarTrigger`'s own guard against mid-type resets would otherwise silently swallow that too), fixing the plain Bold/Italic toolbar popping back up "behind" the composer the instant it closed.
  - `CommentPopover`/`CommentsPanel` restyled to float borderless next to their anchored text (margin-comment style, closer to how most other editors present comments) instead of a boxed sidebar list; the Reply/Resolve/Delete row now only shows on hover, and `CommentsPanel` renders nothing at all (not an empty-state message) when there are no comments. Hovering a comment's highlighted text now echoes onto its card in the panel and vice versa (`useHoveredComment`), and clicking a card in the panel scrolls to and briefly re-highlights its anchored text.
  - `Ctrl`/`Cmd`+`Alt`+`M` opens the comment composer on the current selection (the same shortcut most other editors use), matched on the physical key (`event.code`) rather than the character it produces — Option/AltGr remaps what "M" types on Mac and several EU keyboard layouts, which would otherwise silently break the shortcut there.
- **Version history** — point-in-time document snapshots via a new `versions` IndexedDB object store (`saveDocumentVersion`/`loadDocumentVersion`/`deleteDocumentVersion`/`listDocumentVersions`, `DB_VERSION` bumped 2 → 3, additive), `useDocumentVersions`, and `createPeriodicVersionSnapshotter` for "just handle it" periodic snapshots with oldest-first pruning past a `maxVersions` cap. Restoring a version needs no new function — it's the same `applyDocumentTemplate` templates already use. See `examples/07-version-history/`.

### Fixed

- `canvasBlockType` was defined and used internally (`registerBuiltInBlocks` already wired it in) but never re-exported from the package's public entry point (`src/index.js`/`src/index.d.ts`) — every other block type had an individual opt-in export, canvas didn't. Opting into a hand-picked subset of blocks that included canvas (`registerBlocks(registry, { canvas: canvasBlockType, ... })`) silently received `undefined` for it. Now exported like every other block type, both from JS and the `.d.ts` types.
- `exportDocumentJSON`'s README example and `.d.ts` type both implied it returns a plain `{ rootId, blocks, runs }` object — it actually returns a JSON *string* (it's the "view source"/copy-out format), always did. Fixed both; `JSON.parse()` it first when feeding the result into `useEditor({ doc })` or `saveTemplate`.
- `examples/lan-collab/` and `examples/collab/`: two brand-new tabs/peers joining the same room at nearly the same moment would deadlock forever — each discovered the other before either's "am I alone" seed timeout fired, so neither ever seeded a starter document, and since both stayed empty there was nothing for either side's sync handshake to actually deliver. Fixed in both examples with a deterministic tie-break (whichever peerId sorts lower seeds, decided independently and synchronously by each side, same idea as the existing WebRTC `initiator` tie-break) applied *before* the connection's own initial sync handshake runs, so that handshake picks up real content naturally instead of two empty snapshots meeting in the middle. Found while verifying the new live-cursor/auto-reconnect-watchdog example code in a real two-tab browser session; the same root cause was then confirmed and fixed in `examples/collab/` too.

### Infrastructure

- Added a real Playwright e2e suite (`test-e2e/`, `npm run test:e2e`) covering the comment feature's core flows against a real browser (real Selection API behavior, real click/hover dispatch, real layout — the things jsdom's own much larger vitest suite can't verify), configured against `examples/06-comments/` on a fixed port so it doesn't collide with other example dev servers.

## [0.2.0]

### Added

- **Real-time collaborative editing**, built as a custom block-tree CRDT (not a generic text-CRDT library) so the package stays zero-runtime-dependency:
  - `src/crdt/` — a logical clock (HLC), an ordered-list CRDT for block positions, and a last-write-wins registry for props/type/run-text fields.
  - `EditorStore` now merge-safely tracks every insert/remove/move/edit via that CRDT core, with a new `applyRemoteOperation` entry point kept structurally separate from `History` so remote edits can never enter local undo/redo.
  - `src/sync/` — a WebRTC transport (`PeerConnection`, `CollabSession`, `syncProtocol`) carrying the same CRDT envelopes, with transparent message fragmentation and real backpressure handling for large payloads (e.g. embedded video/file data URLs).
  - `createWebSocketSignaling()` — a generic `SignalingChannel` over plain WebSocket, for manual/shared-rendezvous setups (a relay on your LAN, no internet required, or any host if you want internet-wide reach). A minimal reference relay server lives in `tools/lan-relay-server/` (not part of the published package).
  - Presence/awareness — `CollabSession.setLocalPresence`/`getPresence`/`onPresenceChange` and the `usePresence` hook, for live cursors and "who's online," entirely separate from the document CRDT.
  - Opt-in tombstone garbage collection — `store.pruneTombstones()`/`getTombstoneCount()` and `createPeriodicTombstoneGC()`, safe specifically because reconnects always resync via a full document snapshot rather than replaying historical ops.
  - "Turn into" block-type conversion is now an in-place mutation (same block id) instead of delete-and-recreate, so concurrent conversions of the same block merge as one field conflict instead of producing duplicate blocks.
- **Offline-first persistence** — `usePersistedDocument`, `createAutoPersistence`, and the underlying IndexedDB primitives (`savePersistedDocument`/`loadPersistedDocument`/`deletePersistedDocument`/`listPersistedDocumentIds`). Works standalone or alongside `CollabSession`.
- **PWA / offline app-shell support** — `useServiceWorkerUpdate`, for surfacing "a new version is available" against any service worker registration (host apps bring their own service worker setup, e.g. via `vite-plugin-pwa` — see `examples/offline-persist/`).
- `EditorStore.subscribeAll` (+ `History` passthrough) — a whole-document "something changed" change hook, distinct from the existing per-id `subscribe` used for render isolation.
- New runnable examples: `examples/collab/` (BroadcastChannel signaling, same-browser demo), `examples/lan-collab/` (WebSocket relay signaling, real multi-device/LAN), `examples/offline-persist/` (IndexedDB persistence + PWA), and a numbered `examples/01-quickstart/` … `04-styling/` learning ladder for the new one-call API below (see `examples/README.md`).
- **`useEditor()` + `<NoteloomEditor>`** — a one-call path to a fully working editor (store + both registries pre-populated with every built-in type, undo/redo, clipboard, slash/emoji/@-mention menus, floating format toolbar, keyboard shortcuts, block-range drag, all wired up), replacing the ~40-line manual setup previously required for the common case. Purely additive — the granular API (`EditorStore`, `EditorProvider`, `createBlockRegistry`, individual hooks, ...) is unchanged and still the documented path for anything this doesn't cover (see README's "Advanced: the granular API" section).
- **TypeScript type definitions** (`src/index.d.ts`, hand-written, published as `dist/index.d.ts`) covering the public API — no `.js`/`.jsx` source changed to produce it. `npm run typecheck` (`tsc --noEmit` against the declaration file) now also runs in CI.

### Fixed

- A pre-existing bug where converting a `callout` (a container with no `titleRunIds` of its own) to/from a `titleRunIds`-based type (`listItem`, `toggleHeading`) corrupted the target's `titleRunIds`/`contentIds` by misreading child block ids as text run ids.
- Several bugs found only through real two-peer/real-browser testing along the way: a multi-op batch (e.g. block-type conversion) only broadcasting its last op's change to peers, not all of them; a remote edit landing mid-keystroke being silently reverted by the next local undo; large embedded files failing to sync at all (`RTCDataChannel`'s message-size limit) and then failing differently once chunked (no backpressure against the channel's own send queue); a demo bootstrap race that could reset a room's real content back to a blank starter document.
